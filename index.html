CodeSentry

AI-Powered Code Review System

"Can a hybrid system combining conventional static analysis with RAG-augmented large language models detect a significantly broader class of software defects, including architectural and semantic issues, than either approach alone?"

Problem Statement

Manual code review is the single largest bottleneck in modern software delivery. Studies show reviewers miss up to 40% of defects under time pressure. Existing automated tools fall into two silos: rule-based linters that catch syntax and style violations but are blind to semantic, architectural, and contextual issues; and standalone LLMs that lack grounding in the actual codebase, leading to hallucinated or generic feedback. Neither approach alone provides the depth and breadth required for production-grade review. And even when a tool does catch something, the output is rarely actionable: a wall of linter warnings or a paragraph of AI commentary still leaves a human to decide whether the code is good enough to merge, which is exactly the decision CI/CD pipelines need automated.

Literature Review / Market Research

SonarQube and CodeClimate provide rule-based static analysis but cannot reason about intent or architecture. GitHub Copilot offers AI suggestions but operates without project-wide context. Research by Li et al. (2023) on LLM-based review and Gao et al. (2024) on RAG for code understanding show promise but lack integration with established linting pipelines.

Research Gap / Innovation

No existing CLI tool combines deterministic, multi-language static analysis with context-aware, provider-agnostic LLM review in one CI-ready pipeline. CodeSentry closes that gap in four stages: static analyzers tuned per language, a RAG-grounded review that works with whichever LLM provider you configure (commercial or self-hosted) so the model reasons about your actual codebase instead of guessing, a deterministic 0-100 quality score built from those findings, and a rule engine that checks the score to automatically pass or fail a CI/CD pipeline.

System Methodology

Dataset / Input

Accepts any source repository as input via the CLI. Files are recursively scanned, filtered by configurable exclusion rules, and semantically chunked into function/class-aware segments with overlapping windows for embedding. --diff mode restricts a run to only git-changed files for fast PR checks.

Model / Architecture

Layer 1: language-aware static analyzers, including Pylint, Flake8, Bandit, and Radon for Python, ESLint for JS/TS, go vet and gofmt for Go, Clippy for Rust, RuboCop for Ruby, Checkstyle for Java, and cppcheck for C/C++. Layer 2: code chunks get embedded with sentence-transformers/all-MiniLM-L6-v2, stored in ChromaDB, and retrieved by cosine similarity to augment prompts sent to any configured LLM provider, whether that's OpenAI, Anthropic, Google Gemini, Azure OpenAI, Hugging Face, or a fully local Ollama model, for context-grounded AI review.

The Four-Stage Pipeline

01

Multi-Language Static Analysis

8 languages, each running its own tool set on whatever's installed. Missing tools get skipped, not treated as failures.

02

Provider-Agnostic AI Review

RAG-grounded review against any LLM backend. Swap providers in config.yaml or with --provider, no code changes needed.

03

Deterministic Quality Score

A 0-100 score plus a letter grade, built from weighted, per-file-normalized static findings. It's deterministic, so it still works with --no-ai.

04

Configurable Rule Engine

A YAML-defined pass/fail policy (for example, score at least 70, zero security issues) that exits non-zero to gate CI/CD automatically.

Results & Analysis

Defect Coverage 89.8%

Evaluated across 5 open-source Python projects (Click, HTTPX, Black, SQLModel, Arrow). Detection rates were measured in 4 categories: Security (93%), Code Quality (89%), Architecture (86%), and Best Practices (91%). The averaged defect coverage of 89.8% is a +45.6% improvement over static-only analysis, which averaged 44.2% across the same categories.
